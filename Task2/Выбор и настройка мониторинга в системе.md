# Мотивация

1. Своевременное реагирование на инциденты и проблемы
* Алерты сократят время реагирования на инцденты (сейчас о все проблемы сигнализируют клиенты).
* Мониторинг позволит показать реальное состояние системы.
* Повысит качество релизов -- выявление проблем на начальных этапах (возможность оперативного отката на предыдущую версию)
2. Оптимизация ресурсов.
* Выявление узких мест в системе.
* Вовремя принять решение по вертикальному масштабированию.
3. Уменьшит количество жалоб со стороны клиентов и пользователей API.

# Выбор подхода к мониторингу

Будет использоваться комбинированный подход: RED, USE, 4 золотых сигнала.

# Метрики

## API сервисы

 Метрика | Labels | Предназначение |
|-------------|-------------|-------------|
| Number of requests (RPS)  | service_name, endpoint  | Оценка нагрузки  |
| Duration | service_name, endpoint, method | Оценивает длительность обработки операции. Например, расчет стоимости не должен превышать 30 минут.
| Number of HTTP 500 | service_name, endpoint, method | Количество ошибок на сервере
| CPU % | service_name | предотвращение перегрузок
| Memory Utilisation | service_name | контроль загрузки ресурсов, предотвращение перегрузок.|


## DB
Метрика | Labels | Предназначение |
|-------------|-------------|-------------|
| Memory Utilisation  | db  | предотвращение нехватки памяти, оптимизация кэшировани  |
| Number of connections | db | контроль лимитов подключений, выявление утечек.
| Size of db instance | db| планирование масштабирования хранилища.

## RabbitMQ
Метрика | Labels | Предназначение |
|-------------|-------------|-------------|
| Number of dead-letter-exchange letters in RabbitM  | queue_name  | обнаружение проблемных сообщений.   |
| Number of message in flight in RabbitMQ | queue_name | Оценка загруженности очереди, прогнозирование потенциальных задержек|
| CPU % |  | предотвращение перегрузок
| Memory Usage |  | контроль загрузки ресурсов, предотвращение перегрузок.|

# План действий
1. Создать инстанс time-series базы (Prometheus, Grafana)
2. Настроить экспорт метрик.
3. Реализовать пересичленные метрики в приложениях.
4. Настроить Dashboard в Grafana.
5. Определить пороговые значения и настроить alert в месенджеры для оперативного реагирования рабочей группы (дежурный инженер/devops/системный аналитик/разрабочик)
6. Переодический аудит метрик.
